# Follow-up register

**Everything a slice notices and does not fix lives here, with what became of it.** One row per
problem. A „Noticed, not fixed" line, a recommendation for a later slice, a question a handover
leaves open, a case file's finding outside its own slice — each is filed here **in the slice that
noticed it, in that slice's own final commit**, so nothing depends on anyone remembering a
handover. The rule that says so is in `ga40prj/CLAUDE.md` → „Ending a slice".

This is not Ciprian's defect log (Slice #36.11 — a different file with a different author), and it
is not a review loop: it exists so things are not lost, not to generate work. Per-route test gaps
are not repeated here either — `CATALOGUE_NOT_YET` in `src/lib/testing/catalogue-map.ts` is that
list, and one row below points at it.

`src/__tests__/follow-up-register.test.ts` recounts the table and fails when this block disagrees

`resolved` row names no commit.

## The bar for an entry

An entry has a **runtime consequence** (a defect, a data risk, user-visible copy that is wrong or
English in the Romanian UI), is a **test gap**, is **tooling or debt with a concrete cost**, or is a
**concrete proposal** that says what to do. **A wording preference is never an entry** — not about
documentation, rule files, comments or handover text, and not about the register of a UI sentence
that is already correct. That class is what kept the review rounds running for weeks
(`C:\dev\CLAUDE.md` → „Adversarial review rounds are SUSPENDED"); the register does not rebuild it.

Nothing is filed from memory: every row carries evidence someone actually looked at.

## Fields

| Field | What goes in it |
|---|---|
| **ID** | `FU-nnn`, the next free number. Never reused, never renumbered, never deleted — a row that stops mattering changes status. |
| **Raised** | `date slice ref` for each time it was noticed, `;`-separated. `ref` is a commit, a handover file, a case id, or `§` of a hand-kept list. The same problem noticed three times is **one** row with three refs. |
| **Kind** | defect · data risk · test gap · debt · copy/i18n · tooling · recommendation · next-slice idea |
| **Area** | The part of the app: Auth, People, Documents, Properties, Associations, Groups & tags, Search, Import, AI, Reference data, Versioning, Map, Admin & settings, Help, UI shell, i18n, DB & migrations, Cloud sync & delivery, Tests & e2e, Tooling & CI. |
| **Summary** | One sentence: what is wrong, or what is proposed. Not the story of finding it. |
| **Evidence** | `path:line` at the commit that last checked it, a commit, or a case id. |
| **Impact** | **data** — could lose or corrupt a record · **user** — Ciprian would see it · **dev** — only a developer would · **cosmetic**. A test gap is `dev` unless the untested path is itself a live data risk. |
| **Size** | **XS** under an hour · **S** about half a day · **M** about a slice · **L** more than one slice. |
| **Status** | One of the six below. |
| **Status note** | For `resolved`, the slice and **commit** that did it; for `ignored`, the one-line reason; for `duplicate`, the `FU-nnn`; for `superseded`, what replaced the code. For `open`, optionally the fix in one line. **„Unverified:"** opens the note of an open row nobody could confirm either way from the code (it depends on a live database, a UAT box or a screen). |
| **Last checked** | The date someone last compared the row against the code. |

## Statuses — each one ends a question

| Status | Means | Moves to |
|---|---|---|
| `open` | Still true at the last check. | `planned`, `resolved`, `ignored`, `duplicate`, `superseded` |
| `planned` | A named slice will take it (the note names it). | `resolved`, or back to `open` if the slice drops it |
| `resolved` | Fixed. **Only ever written with the commit that fixed it**, so the claim is one `git show` away. | — |
| `ignored` | Deliberately not done; the note says why. Reversible by reopening. | `open` |
| `duplicate` | The same problem as `FU-nnn`, filed twice by mistake. | — |
| `superseded` | The code it was about no longer exists. | — |

## Updating it

- **File** a new row at the bottom with the next ID and `open`. Before filing, search the table —
  a problem already here gets a new `Raised` ref, not a new row.
- **Close** a row by changing its status and note in place, in the commit that fixed it, and set
  **Last checked**. Never delete a row.
- **Keep the summary block true** in the same commit. The guard test will say so if it is not.
- Rows `FU-001`–`FU-207` were filed together by Slice #36.10's harvest of commit bodies, the
  `Handover.34.nn.md` files, `Noticed.not.Fixed.01.to.10/11.to.20.docx`, the case files'
  „Notes from the runs", the catalogue and `slice-log-archive.md`, each checked against `d1b4fd6`.
  They are ordered open first (by impact), then ignored, resolved (by fix date) and superseded. From
  `FU-208` on, rows are in the order they were filed.
